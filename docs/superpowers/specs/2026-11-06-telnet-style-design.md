# PTT Marquee：telnet 終端機風格改版設計

日期：2026-11-06

## 目的與原因

使用者想要「傳統終端機瀏覽 PTT 的感覺」，具體指的是以前用 **telnet** 上 PTT 的畫面。現在的 UI 是現代 macOS 風格（毛玻璃、圓角卡片、膠囊標籤、SF Symbols 圖示、原生 popover），跟這個感覺衝突。這次改版只改外觀與操作方式，抓取、隊列、輪詢等功能邏輯不變。

## 目標

1. 主畫面（聊天室）改成 telnet PTT 的樣子（使用者在草圖中選了「A. 原汁原味」）。
2. 設定面板也改成終端機風格，並以「整個視窗切換成設定畫面」的方式呈現（使用者選了 A）。
3. 操作從圖示按鈕改成按鍵文字，例如 `(P)暫停`；鍵盤和滑鼠點擊都要能用。

## 非目標

- 不改資料抓取、去重、推播間隔、輪詢、持久化等邏輯（`Services/`、`Models/`、`ChatViewModel` 的行為）。**唯一例外**是下面「推播分組」這一項對 `MessageQueueManager.enqueue` 的修改。
- 不做真正的 telnet 連線，資料來源仍是 www.ptt.cc 網頁版。
- 不提供「現代風格／終端機風格」切換，舊風格直接取代。（我的決定）

## 反目標（做了反而算失敗）

- 看起來像「有黑底的 macOS App」：殘留圓角卡片、膠囊、SF Symbols 圖示、原生 popover 或 sheet。
- 現有功能因為改版而消失，或變得只能用鍵盤操作。

## 已決定的設計

### 整體視窗

- 背景是純黑 `#000`，拿掉毛玻璃與 `Color.black.opacity(0.35)` 疊層。視窗邊角最多保留很小的圓角。（我的決定）
- **透明度設定只作用在黑色背景**，文字和色塊維持不透明。（我的決定；目前是整個 View 套 `.opacity`，連文字都會變淡）
- 全部使用等寬字：英數用 Menlo，中文退回系統字型（PingFang TC）。字體大小設定照舊（11～18 pt）。（我的決定）
- 保留無邊框、可縮放、置頂、鎖定、記憶位置等現有視窗行為（`WindowController.swift` 不需要大改）。

### 配色（PTT 原生 ANSI 16 色）

| 元素 | 顏色 |
|---|---|
| 推 | 亮白、粗體 |
| 噓 | 亮紅 `#ff5555` |
| → | 暗紅 `#a80000` |
| 使用者 ID | 亮黃 `#ffff55` |
| 推文內容 | 暗黃 `#a8a800` |
| 時間 | 灰 `#808080` |
| 標題列 | 藍底 `#0000a8`、白字 |
| 提示列 | 青底 `#00a8a8`、黑字；按鍵區塊為灰底 `#a8a8a8` |
| 反白（游標列、目前選項） | 青底 `#00a8a8`、黑字 |

### 主畫面版面（由上到下）

1. **藍底標題列**
   - 看板模式顯示 `【看板】Gossiping`；單篇實況模式改成顯示文章標題，取代現在的橘色橫幅。
   - 右側顯示狀態：待播數量（`● 待播 12`），以及「暫停」「已固定」「篩選中（只看推／只看噓）」等狀態文字。
   - **拖曳視窗靠這條標題列**，取代現在的 `PTT` 把手；鎖定時不能拖曳。（我的決定）
2. **留言區**
   - 一行一則：`推 ID: 內文 ……… 11/06 10:26`，時間靠右。沒有卡片、外框、圓角、間距。
   - 看板模式下，**來源文章換篇時**插入一條灰色分隔線 `─── [問卦] 標題 ───`，每行不再重複顯示文章標籤。單篇模式不需要分隔線。
   - 新留言直接出現，拿掉滑入與淡入動畫。（我的決定）
   - 滑鼠移過某一行時，那行用反白色表示，就像 telnet 的游標列；拿掉現在的 hover 外框發光。（我的決定）
   - **點擊行為**：點分隔線（文章標題）會在瀏覽器開啟原文；點留言行不做任何事，避免使用者只是想點一下讓視窗取得焦點時，卻跳出瀏覽器。（我的決定；現在只有留言上方的文章標籤可以點，而那個標籤會被拿掉）
   - **推播分組**（使用者選擇 C）：實際資料中，每輪抓到的新推文通常每篇只有 1～3 則，而且多篇交錯，每換一篇就畫分隔線會讓畫面有一半是分隔線。因此 `MessageQueueManager.enqueue` 在把一批新推文加入隊列前，先**依文章分組**：
     - 組與組的順序，依各篇在這批資料中第一次出現的順序。
     - 同一篇內維持原本的順序。
     - 只在同一批之內重新排列，不跨批次，也不動隊列中已經排好的推文。
     - 使用者已接受代價：推播順序不再嚴格照時間，不同文章的推文會一批一批出現。
     - 單篇模式只有一篇文章，分組沒有影響。
   - 分隔線依「目前畫面上顯示的列表」（`filteredMessages`，套用篩選後）中相鄰兩則是否屬於不同文章來決定。畫面最上方第一則前面一律補一條分隔線，所以 150 則上限把前面裁掉時，也不會出現沒有標題的一組。
   - 單篇模式沒有分隔線，標題列已經顯示文章標題；要開原文就用右鍵選單。
   - **長推文**：自動換行，第二行起懸掛縮排，對齊在 `ID:` 之後，不截斷內容。（我的決定；「一行一則」指的是不做卡片，不是強制單行）
3. **新留言提示**：使用者往上捲時，不再顯示浮動的「回到底部」膠囊，改成在提示列正上方出現一行反白提示 `▼ 有 12 則新留言  (End)回到底部`，可點擊。往上捲時暫停自動捲動的邏輯照舊。（我的決定）
4. **青底提示列**：顯示目前模式（看板串流／單篇實況）與可用按鍵，例如：
   `(P)暫停 (F)篩選 (B)看板 (L)鎖定 (T)置頂 (S)設定 (?)說明 (X)離開`
   - 單篇模式多一個 `(Q)返回看板`。
   - 每個按鍵文字都可以用滑鼠點。
   - **窄視窗規則**：視窗預設寬 360pt、最小 280pt，整排提示寬度約 340pt 以上。寬度不夠時，提示列會自動折成兩行，不截斷、不換成圖示。原則是用滑鼠也一定點得到每一個功能。（我的決定）

### 按鍵對照

| 按鍵 | 動作 | 取代現在的 |
|---|---|---|
| P | 暫停／繼續推播 | 暫停按鈕 |
| F | 依序切換「全部 → 只看推 → 只看噓」 | 篩選選單 |
| B | 進入看板清單畫面 | 看板下拉選單 |
| L | 鎖定／解除視窗位置 | 鎖頭按鈕 |
| T | 置頂／取消置頂 | 圖釘按鈕 |
| S | 進入設定畫面 | 齒輪 popover |
| ? | 進入說明畫面 | 說明 popover |
| X | 結束應用程式 | 右上角 X |
| Q | 在單篇模式：返回看板串流；在子畫面：返回聊天室 | 單篇實況的 ✕ 按鈕 |
| End／G | 回到底部（MacBook 沒有 End 鍵，所以加上 G 作為別名） | 回到底部按鈕 |

- 單鍵操作只在視窗是焦點（key window）時有效，使用者已同意。
- `⌘⇧L`／`⌘⇧P` 的全域鎖定快捷鍵保留不變。
- 實作提醒：local monitor 處理掉的按鍵要回傳 `nil`，否則沒有 first responder 時，系統會發出 NSBeep 提示音。
- `X` 直接離開會有誤觸風險，建議跳出一行確認 `確定要離開嗎？(Y/N)`。（我的決定）

### 子畫面（整個視窗切換）

設定、看板清單、說明三個子畫面都用同一種模式：**聊天區整個換成該畫面，標題列與提示列跟著換內容**，按 `Q`（或點提示列）返回聊天室。在子畫面期間，推文仍在背景抓取與排隊，返回後接著播放。

共通操作：`↑↓` 移動選項、`←→` 調整數值、`Enter` 確定或進入輸入、`Q`／`Esc` 返回；滑鼠點擊選項等同移到該項並按 Enter。

**設定畫面**（標題 `【個人設定】`，選項與現在的設定面板一一對應）：

```
▶ 視窗永遠置頂          [ON ]
  固定視窗位置          [OFF]
  看板抓取間隔          ■■■□□□□□  8 秒     (5～30)
  單篇抓取間隔          ■■□□□□□□  3 秒     (2～15)
  背景透明度            ■■■■■■■□ 85%      (25～100%)
  字體大小              ■■□□□□□□ 13pt     (11～18)
  前往看板： ____________     ← Enter 進入輸入，再按 Enter 送出
  鎖定文章： ____________
  清空畫面留言
  結束應用程式
```

- 方塊條用 ←→ 調整，步進值沿用現在 Slider 的 step；滑鼠點擊方塊條的某一格，直接跳到那個值。（我的決定）
- 單篇實況期間，「鎖定文章」這一列改成顯示目前的文章，按 Enter 會退出實況，對應現在的「退出實況」按鈕。
- 輸入欄有底線，進入輸入時顯示游標。**輸入期間停用所有單鍵快捷鍵**（例如輸入 `Stock` 時不能觸發 S、T、C），按 Enter 送出、Esc 取消；網址或看板名稱無效時，在提示列顯示紅字錯誤。

**看板清單畫面**（標題 `【熱門看板】`）：用 PTT 看板列表的樣式列出 `PTTBoard.presetBoards`，目前看板以反白或標記顯示，Enter 切換看板並返回聊天室。

**說明畫面**（標題 `【使用說明】`）：把現在 `HelpSheetView` 的內容改成純文字分段，可以捲動；內容要更新成新的按鍵操作。

### 右鍵選單

右鍵選單是 macOS 原生元件，外觀無法改成終端機風格，因此保留功能，只調整文字，去掉 emoji，改成簡潔的文字，例如 `鎖定此篇為實況聊天室`、`在瀏覽器開啟文章`、`複製留言內文`。沒有對應按鍵的選項不加 `(X)` 提示，避免跟主畫面的按鍵意思混淆（例如主畫面的 L 是鎖定視窗）。（我的決定）

- 視窗右鍵選單中的「使用說明」改成切換到說明畫面，不再開 sheet。

### 錯誤訊息

網路錯誤（現在的 `errorMessage`／「重試中」）和無效網址、無效看板名稱，統一在提示列上方以一行紅字顯示，成功抓取一次後消失。（我的決定）

### 空狀態

- 改成終端機文字，例如 `正在連線到 Gossiping 看板……` 加上一個閃爍游標，拿掉 `ProgressView`。
- 修正寫死的「3 秒更新」，改用實際的 `articleRefreshInterval`。
- 篩選後沒有任何留言時（例如只看噓但沒有噓文），顯示 `（目前沒有符合篩選的留言）`，不要整片空白。

## 連帶要更新的文件

- `CLAUDE.md`：架構段落中跟 View 有關的描述。

## 限制

- macOS 13+、SwiftUI + AppKit，不引入第三方套件。
- 新增或刪除原始檔後必須執行 `xcodegen generate`（`project.yml` 是唯一來源）。
- 專案沒有測試 target；驗證方式是用 `xcodebuild` build 成功，並實際啟動 app 目測。
- 不是 git repo。

## 交給實作者決定

- View 的拆分方式與檔名，例如 `TerminalTheme`、`TerminalScreen` 列舉、各子畫面 View。
- 鍵盤事件的實作方式，例如 `NSEvent` local monitor 或 SwiftUI `onKeyPress`（macOS 14+ 才有，所以 13 需要用其他方式）。
- 中英文混排時如何對齊時間欄位，例如整行用 `HStack` 加 `Spacer`，或計算字元寬度。
- 分隔線寬度如何填滿視窗寬度。
- 「已讀標記」等細節的取捨，只要不違反上面的反目標即可。
